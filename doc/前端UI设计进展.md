## 4. 阶段九：亚克力毛玻璃环境下的文字对比度与清晰度重构专项

针对用户反馈“效果还不错，就是文字看不清”，结合用户提供的截图进行了针对性诊断与重构：

### 4.1 文字看不清的原因分析
1. **暗灰色在磨砂背景上对比度骤降**：先前次级文本（`--text-secondary: #9aa0a6`）、三级文本与占位符（`--text-tertiary: #606770`）均采用中低明度的暗灰系。当背景换为高细节透光壁纸后，暗灰色文字直接被透射上来的底图噪点与漫反射光晕吞噬，对比度跌落至 WCAG 2:1 以下。
2. **底板遮光度偏低导致的文本底色抖动**：当透明度处于 0.62 且滑过浅色/鲜艳壁纸区域时，底板缺乏足够的衬底反差，导致深色与灰色文字混杂难辨。

### 4.2 核心重构与对比度升级
- **基底遮光度科学加固**：
  - 默认暗色亚克力底色由 0.62 优化提升至 `rgba(20, 23, 31, 0.72)`，配合 `blur(30px) saturate(190%) contrast(105%)`，既确保了磨砂漫反射色彩穿透，又为文字提供了坚实纯净的高对比底色衬托。
- **高对比阶梯字色系统 (WCAG AAA 标准)**：
  - **主标题（Primary）**：升级为纯白 `#ffffff`，辅以微妙的自然文字下沉暗影（`text-shadow: 0 1px 2px rgba(0,0,0,0.3)`），确保标题不论在任何明暗壁纸上都如激光雕刻般清晰。
  - **次级文本（Secondary）**：由暗灰 `#9aa0a6` 跃升至亮板色 `#e2e8f0`（对比度提升 300%），用于路径、操作按钮、选中状态等。
  - **三级辅助与标签（Tertiary）**：由死灰 `#606770` 升级至清晰亮蓝灰 `#94a3b8`，彻底解决搜索框占位符、分类标题（固定/最近）、元数据标签（位置/版本）看不清的问题。
  - **搜索占位符**：重定义为清晰半透明白 `rgba(255, 255, 255, 0.50)`，清晰提示又不抢占视线。
- **界面各要素清晰度逐一重构**：
  - **搜索列表项**：副标题路径（`Code.exe`、`D:\Projects`）改用等宽字体加明度呈现；分类徽标（应用/文件夹/文档）增加微光轮廓（`border: 1px solid rgba(255,255,255,0.12)`）与高对比字色。
  - **右侧预览区**：元数据标签 `位置`、`版本` 使用 `#94a3b8`，对应键值使用 `#ffffff`；次要操作按钮（定位、取消固定、复制路径）由昏暗块升级为微磨砂高亮块（`rgba(255,255,255,0.08)`），字色提亮为 `#ffffff`。
  - **底部状态栏**：所有 `<kbd>` 快捷键按键加厚背景并使用明亮字体，快捷键说明文字清晰可辨。
  - **图标容器对比度**：为每个文件类型图标容器添加对应色系的柔和半透发光边框，图标更加立体生动。

## 7. 阶段十二：稳定固定尺寸设计与全向手动缩放引擎专项总结

针对用户提出的明确要求：**“我的意思是固定大小，就是切换也不变，但是可以通过手动改变大小”**，本阶段对搜索启动窗口的几何尺寸模型与缩放交互机制进行了系统性重构：

### 7.1 痛点剖析与“固定大小，切换也不变”的核心原则
1. **彻底消除尺寸跳跃与视觉抖动**：
   - 先前设计中，系统依据当前选中项是否为“可预览文件”动态在 `640px` 与 `900px` 之间切换窗口宽度，导致用户使用方向键在应用（VS Code）与代码文件（`EasyNote.md`）之间快速穿梭时，整个窗体频繁横向暴增暴减，产生剧烈的视觉跳动与割裂感。
   - **重构原则**：窗口外形几何尺寸（宽度、高度）被严格定义为常量，**任何键盘切换、鼠标点击、分类筛选流转、搜索输入均严禁程序化篡改窗口尺寸**！
2. **稳定双栏空间分工（Stable Two-column Split）**：
   - 窗口固定采用经典优雅的双栏结构（左侧主搜索与结果列表 + 右侧固定 320px 属性详情与代码预览栏）。
   - 无论用户聚焦在**文件**、**桌面应用程序**、**本地文件夹**还是**剪贴板记录**：
     - **文件**：呈现文件名、类型标签、物理路径、大小与修改时间，并在下方渲染等宽代码/Markdown 预览区及常用操作快捷键；
     - **应用程序**：呈现应用标题、可执行程序路径、版本号、运行状态及启动快捷键；
     - **文件夹**：呈现目录名称、目录路径、占用大小、最近访问时间及打开目录快捷键；
     - **剪贴板**：呈现文本内容高亮代码块、记录时间、字符数及快捷复制提示。
   - 双栏内容平滑更新，左侧结果区与右侧信息区分工明确，窗口轮廓纹丝不动。

### 7.2 全向手动尺寸调整引擎 (Manual 2D Resize Engine)
依据用户“但是可以通过手动改变大小”的指导，为用户赋予了对窗口尺寸绝对自主的控制权：
1. **右下角双向缩放抓手 (`.launcher-resize-corner`)**：
   - 位于窗口右下角（`cursor: se-resize`），提供微光三角指示标。
   - 按住拖拽即可**同时自由调节宽度与高度**，鼠标轨迹实时联动，自由拉伸。
   - **双击复位**：双击右下角缩放抓手，窗口瞬间平滑恢复为出厂推荐默认尺寸（`860px × 440px`）。
2. **底部高度调整边缘 (`.launcher-resize-bottom`)**：
   - 位于窗口底部边缘（`cursor: ns-resize`），居中带微质感高斯指示条，按住上下拖拽可单独定制窗口纵向高度（220px ~ 780px）。
3. **右侧宽度调整边缘 (`.launcher-resize-right`)**：
   - 位于窗口右侧边缘（`cursor: ew-resize`），按住左右拖拽可单独定制窗口横向宽度（540px ~ 1320px）。
4. **居中对齐几何光标追踪算法**：
   - 针对居中弹窗在屏幕中央的几何特性，缩放引擎内置了精准的物理坐标映射，确保拖动边缘时手柄与鼠标光标 100% 紧贴跟随，绝无延迟漂移。
5. **偏好尺寸本地永久持久化**：
   - 用户手动调整的宽度与高度实时写入 `localStorage`（`anycast_launcher_width` 与 `anycast_launcher_height`）。
   - 页面刷新或下一次唤出窗口时，完美保持用户手工设定的专属窗口比例。

### 7.5 窗口高度调整死锁与文字遮挡彻底根治专项 (960px × 600px 黄金规格 + 响应式 Pin 展架 + 无死区拖拽)
针对用户在实测截图中的关键反馈：**“高太小了，而且无法被调整，默认最小大小文字甚至被遮挡，这不合理”**，本专项对尺寸模型、缩放算子与排版网格实施了根治性重构：

1. **高度无法调整的深层根因与根治方案**：
   - **死锁根因**：原代码在 `onPointerMove` 中引入了 `Math.min(780, window.innerHeight - 160)` 过于严苛的防溢出限制。在非全屏浏览器或常见 1080p 桌面（扣除系统任务栏与浏览器标签栏、地址栏后视口仅约 600~700px）环境下，该限制直接将最大高度钳制在 440~490px 之间，导致用户向下拉伸时被立即锁死，无论怎么拖动都不动；同时原把手热区仅 8px，极难用鼠标精准拾取。
   - **解除死锁与热区放大**：
     - 彻底移除了不合理的高度限制，允许纵向高度随心所欲自由延展至 `min(1000, innerHeight - 30)`；
     - 尺寸作用目标由内部局部容器提升为直接作用于主窗体 `.search-window`（`width` / `height` 统一管理），内部 `.search-body` 采用 `flex: 1; min-height: 0;` 弹性自适应充满，整窗呼吸伸缩浑然一体；
     - **把手热区扩大 2.5 倍**：底边把手有效感应高度扩大至 **20px**，居中高光条加长至 72px；右边把手感应宽度扩大至 **20px**；右下角抓手扩大至 **28px**；拖拽事件挂载在 `window` 全局，绝无丢帧脱手可能。
2. **文字被遮挡的深层根因与自适应响应式重构**：
   - **遮挡根因**：双栏布局下，右侧预览栏切走宽度后，左侧检索区仅余有限空间；先前强行使用固定 4 列网格（`repeat(4, 1fr)`），导致每张 Pin 卡片被压缩到仅 70~90px，标题被类型徽标严重挤占，最终只露出一个首字母（如 `\` 或 `E`）甚至完全被隐匿。
   - **响应式防遮挡自适应网格**：
     - 彻底摒弃固定的 4 列挤压，重构为弹性响应式网格：`grid-template-columns: repeat(auto-fit, minmax(130px, 1fr));`；
     - **永远保障每张卡片至少有 130px 宽**：当窗口较宽时自动平铺为 4 列横排；当窗口处于最小尺寸或用户收缩窗口时，自动平滑折为 2 行 × 2 列优雅排版；
     - 卡片内标题与类型徽标呼吸舒展，**在任何窗口尺寸（即使是极限最小尺寸）下，文字都 100% 完整清晰展示，绝无遮挡**！
3. **更舒适宽敞的默认尺寸与快捷控制**：
   - 默认规格确立为 **`960px × 600px`**（主视窗 960px，主体高度 600px），一次性完整呈现搜索栏、分类栏、快速访问、所有最近使用项以及完整的代码预览区；
   - 顶栏工具栏新增 **`📐 默认 960×600`** 专属重置按钮，同时双击右下角抓手、双击底边、双击右边均可瞬间一键复位默认尺寸。

本阶段严格响应用户对于启动器结构重构与交互体系的 8 项核心要求（“首先搜索有切换入口，整个页面需要一个设置按钮，置顶放置搜索结果上方，筛选只有全部，文件，应用，剪切板，视图有两种，一是显示图标，二是列表，双击是调用系统打开，我需要你做提示，剪切板具有二级筛选，置顶可折叠起来，先不考虑预览的情况”），完成了系统性的高保真落地：

  - `Alt+1`：全部
  - `Alt+2`：文件
  - `Alt+3`：应用

### 9.4 剪切板动态二级筛选栏 (`#clipboardSubFilterBar`)
- **二级维度细分**：
  - `全部`：展示所有历史剪切板快照；

### 9.5 双视图模式：单行列表 vs 大图标卡片
- **单行列表视图 (`.view-list`)**：
  - 经典桌面启动器高密度排版。

- **模式持久化**：用户选择的视图模式永久记忆在 `localStorage`（`anycast_view_mode`）中，刷新与重开窗口绝不丢失。

### 9.6 双击系统调用与高保真操作提示 (`launchViaSystem`)
- **系统调用机制**：

### 9.7 置顶快速访问可折叠展架 (`#togglePinnedBtn`)

### 9.8 单栏 100% 满宽与预览侧栏隐去

## 11. 阶段十四：视觉去噪与结构层级二次重构专项总结

依据用户最新针对“你别死板啊，有些东西还是使用图标的好，但是不要使用五彩斑斓的那种，置顶位于全部那一栏上面，最近使用和搜索结果互通，无搜索时使用最近使用，不要加莫名其妙的外边框和底色。再改改，系统图标你做不出来就用一些图标占位”的明确指示，本阶段完成了如下精细重构：

### 11.1 物理层级重构：置顶快速访问物理置于“全部”分类栏之上
- **DOM 结构调整**：
  - 此前置顶展架渲染于下部结果容器内部（位于分类标签栏下方），造成层级倒置。
  - 本阶段将 `#pinnedShelfSection` 物理移至 `#categoryFilterBar`（“全部/文件/应用/剪贴板”那一栏）的**正上方**，形成：
    `搜索输入框` → `置顶快速访问` → `分类筛选与操作栏` → `统一结果展示区` 的逻辑主轴。
- **动态空间让位**：
  - 当处于空闲（无搜索输入）状态时，置顶快速访问展示在输入栏与分类栏之间，可一键点击或双击直达，支持点击 `▲ 折叠` / `▼ 展开` 自由收折；
  - 当用户在输入框中键入搜索字符（`searchQuery !== ""`）时，置顶区域自动平滑收隐（`display: none`），将 100% 垂直高度让渡给即时检索结果，搜索体验干净纯粹。

### 11.2 “最近使用”与“搜索结果”彻底互通
- **单一结果容器与互通逻辑**：
  - 废除分散的双重展示架构，下部 `#resultPane` 成为统一的展示载体：
    - **无搜索时（`searchQuery === ""`）**：展示“最近使用”（标题标明“最近使用”，支持按“全部/文件/应用/剪贴板”及剪贴板二级细分进行即时过滤）；
    - **有搜索时（`searchQuery !== ""`）**：展示“搜索结果”（即时匹配用户输入词，按分类分段并高亮显示匹配关键字）。
- **统一视图与操作体验**：
  - 无论展示的是“最近使用”还是“搜索结果”，均统一受右上角“视图切换”（单行列表 / 大图标网格）控制；
  - 均支持相同的上下方向键无缝导航、`Enter` 运行，以及双击调用系统程序打开与高保真 Toast 提示。

### 11.3 彻底剔除“莫名其妙的外边框和底色”
- **分类标签栏净化**：
  - 移除 `#categoryFilterBar` 的背景与下边框（`background: transparent; border: none;`），使其天然融入亚克力磨砂深层。

## 23. 阶段二十：置顶卡片取消按钮与徽标防碰撞及悬停平滑置换专项总结

  - **默认状态**：展示类型徽标（“文档”、“应用”），取消置顶按钮完全隐藏（`opacity: 0; pointer-events: none;`）；

    - 类型徽标平滑微缩放淡出（`opacity: 0; transform: scale(0.85);`）；
    - 原地优雅浮现 18×18px 居中纯透明取消置顶按钮（`opacity: 1; transform: translateY(-50%) scale(1);`）；

## 25. 阶段二十一：置顶展架固定图标类卡片、去除横向拉伸、单行平滑滚动与多行网格溢出处理专项总结

针对用户最新指示：“**这个不用拉这么长，与底下相同即可，但是它固定图标类，同时，你需要处理一下内容过多时怎么展示得问题**”，本阶段深入剖析了此前置顶展架被强行横向拉伸、样式与底部图标不一致以及大量置顶项目溢出无法优雅呈现的技术根因，完成了系统级高保真落地：

### 25.1 “不用拉这么长，与底下相同即可，但是它固定图标类”的视觉重构
1. **彻底消除拉伸成细长横条的问题**：
   - 先前采用 `grid-template-columns: repeat(4, 1fr);` 导致 4 个置顶卡片在 860~960px 宽度下被强行平分拉宽至 200px+，图标与文字之间存在大量无意义空白；
   - 彻底废除 `repeat(4, 1fr)` 撑满机制，每张卡片改为固定的精致尺寸（宽度 86px，高度 84px），按真实内容紧凑自适应排列，绝不横向虚胖拉长。
2. **对齐底部大图标卡片排版规范（固定图标类）**：
   - 无论下部的搜索结果处于“列表模式”还是“图标模式”，顶部置顶展架**永远固定为高保真大图标卡片类（.pinned-card）**：
     - **顶部**：34×34px 规范圆角 Squircle 图标容器（附带类别渐变底色与清晰白光矢量 Glyph）；
     - **中部**：纯白单行标题（`VS Code`、`Projects`、`EasyNote.md` 等，单行省略并居中）；
     - **底部**：紧凑类型徽标（`应用`、`文件夹`、`文档`、`代码` 等，居中微徽标）；
     - **右上角**：微透光悬停取消置顶按钮（平时隐藏，悬停卡片浮现，悬停按钮激活柔和绯红微光，点击取消置顶并阻止冒泡）。
   - 视觉语言与下部大图标网格（`.icon-card-item`）达到 100% 像素级统一和谐。

### 25.2 “内容过多时怎么展示”的优雅全套解决方案
当用户置顶了 8 项、12 项甚至 20+ 项时，如果任由其向下无节制堆叠，会挤占甚至遮盖下方的分类栏与搜索结果。本阶段提供了三位一体的立体化交互方案：

1. **默认模式：单行横向平滑滑动轨道（Horizontal Smooth Ribbon）**：
   - 置顶卡片装载于 `#pinnedTrackWrapper` 单行滑动轨道中（`flex-direction: row; width: max-content;`），高度严格锁定在约 85px，**绝不占用任何多余的垂直高度**；
   - **滚轮横向直觉滚动**：鼠标悬停在置顶区域时，拨动鼠标滚轮即可自然平滑横向滚动浏览全部置顶卡片（系统自动将 `wheel` 垂直偏移量映射为 `scrollLeft`）；
   - **左右步进翻页按钮**：当卡片总宽超出容器宽度时，头部右侧自动亮起 `<` 与 `>` 翻页按钮（到头自动禁用，内容不足时完全隐藏），点击即可一次性平滑滚动一屏卡片。

### 38.1 需求定位与核心价值
- **痛点分析**：
  - 用户在日常高频工作中，对核心生产力工具（如 VS Code、终端、常用项目文件夹或核心技术文档）往往希望通过一个专属的全局快捷键（如 <kbd>Alt+C</kbd>、<kbd>Alt+T</kbd>、<kbd>Alt+P</kbd>）实现秒级直达或将窗口拉至最前，而无需先呼出搜索框再键入名称按回车。
- **功能特性规划**：
  1. **独立侧边栏导航**：在设置弹窗左侧导航增设 `⌨️ 快捷直达 (热键绑定)` 标签页；
  2. **全局热键主开关**：顶部提供全局热键直达服务主控开关，支持一键开启或暂停全部热键调度；

  4. **交互式热键录制器 (Interactive Hotkey Recorder)**：
     - 点击列表项的热键徽章或新建面板的录制框，立即进入脉冲高光录制态（提示“按下按键...”）；
     - 捕获用户键盘组合键（如 <kbd>Alt+字母</kbd>、<kbd>Ctrl+Shift+字母</kbd>、<kbd>Win+字母</kbd>），支持自动防冲突校验（检测是否已被其他条目占用）；
     - 按 <kbd>Esc</kbd> 或点击空白处自动取消录制；
  5. **“+ 添加绑定”便捷卡片**：
     - 支持展开式新建卡片，包含目标名称、目标路径、类型下拉框（应用 / 文件夹 / 文件）及快捷键录制框；
     - 提供 **“从列表选择”** 快捷填充按钮，直接从用户“最近使用”列表中提取目标路径与名称，大幅缩短录入成本；
  6. **系统级启动模拟调度与全局热键监听**：
     - 提供“测试运行”模拟按钮，点击后立即触发 Fluent 灵动 Toast 提示（如 `🚀 [全局热键直达 Alt+C] 正在唤醒启动: Visual Studio Code`）；
     - 原型全局监听激活的热键组合（如键盘按下 <kbd>Alt+C</kbd>、<kbd>Alt+T</kbd>、<kbd>Alt+D</kbd>、<kbd>Alt+P</kbd>、<kbd>Alt+N</kbd>），无论处于搜索框还是设置界面，均可无缝触发对应目标的直达唤起模拟。

## 54. 检索位置系统重构与“进入文件夹查找”方案落地（阶段三十六）

### 54.1 需求背景与人机交互痛点剖析
依据用户最新指导：
> **“位置也要额外思考一下，比如进入什么文件夹查找”**

在启动器（Launcher / Search Bar）的使用场景中，用户往往有两类截然不同的“指定位置查找”诉求：
1. **全局预先筛选**：在开始敲击关键词前，明确希望把搜索范围收敛至某磁盘驱动器（如 `D:\`）、某个标准目录（如 `桌面`、`下载`、`文档`）或特定工程工作区（如 `D:\Anycast`、`D:\Projects`、`EasyNote`）；
2. **渐进式钻取（Drill-down / 进入此文件夹查找）**：用户在全盘或模糊检索中首先搜索出了某个文件夹（例如通过搜索 `note` 找到了 `EasyNote` 文件夹），此时用户并不想直接启动打开资源管理器，而是希望**“立即钻入该文件夹内部，继续在其中查找子文件或子项目”**。

如果仅提供死板的几个选项或者繁琐的层层文件浏览弹窗，将彻底破坏 Anycast “极速、沉浸、全键盘流转”的核心体验。

### 54.2 核心设计理念与全链路方案

```
┌───────────────────────────────────────────────────────────────────────────────────┐
│                     Anycast 位置检索与“进入文件夹查找”全链路                        │
└───────────────────────────────────────────────────────────────────────────────────┘
          │
          ├─► 场景 A：从顶部筛选栏主动指定位置
          │     ├─ 点击 [ 📂 位置 ▾ ] 胶囊展开 .filter-location-popover (宽 276px)
          │     ├─ 即时路径搜索过滤框 (#locSearchInput)：输入关键字秒级筛选列表，或直接输绝对路径按回车
          │     ├─ 分组一：系统磁盘与常用目录 (全盘索引/C盘/D盘/桌面/下载/文档)
          │     ├─ 分组二：常用工作区与工程目录 (Anycast/Projects/EasyNote 等)
          │     └─ 底部动作：[ 📂 选择自定义文件夹... ]
          │
          └─► 场景 B：渐进式键盘/右键一键钻取 (Drill-down)
                ├─ 搜索结果或置顶列表中高亮项为文件夹条目 (type: folder)
                ├─ 动作 1：按键盘 【Tab】 键 ──► 瞬间触发 enterFolderSearch(folderItem)
                ├─ 动作 2：右键条目 ──► 浮层展示专属高亮项 【📂 进入此文件夹查找 (Tab)】
                ├─ 效果：
                │    1. 顶部筛选栏自动展开；
                │    2. 位置胶囊动态高亮显示为 [ 📂 文件夹名 × ] (例如 [ 📂 EasyNote × ])；
                │    3. 胶囊悬浮提示显示完整绝对路径 (例如 E:\Projects\EasyNote)；
                │    4. 主搜索输入框清空并重新聚焦，等待输入该文件夹下的子文件关键字；
                │    5. itemMatchesScope 算法自动递归过滤该路径下所有下级文件与目录；
                └─ 退出：点击胶囊上的 × 秒级恢复全盘检索。
```

### 54.3 核心实现细节与功能验证
1. **多层级微晶位置浮层 (`.filter-location-popover`)**：
   - 采用 276px 舒适宽度，与时间日历浮层保持视觉尺寸一致；
   - 顶部内嵌微晶搜索过滤框（带搜索图标与轻量灰色边框），输入即时对下方所有系统磁盘、目录、工作区进行快速过滤，输入绝对路径（如 `E:\Code`）按 <kbd>Enter</kbd> 直接一键应用；
   - 磁盘与目录选项均配备主标题（如 `Anycast`、`工作磁盘 (D:)`）与次级路径小字（如 `D:\Anycast`、`D:\`），清晰指引所在物理地址；
   - 底部配备微晶半透「📂 选择自定义文件夹...」动作按钮。
2. **“进入此文件夹查找”键盘与右键闭环**：
   - **Tab 键智能双重语义**：当当前选中的激活项为文件夹时，按下 <kbd>Tab</kbd> 直接作为“进入此文件夹查找”的瞬发快捷键；在其他场景下保持原有“搜索模式切换”语义，符合直觉且零键位冲突；
   - **右键上下文菜单**：右键任意文件夹条目时，动态插入首选操作 **`📂 进入此文件夹查找`**（右侧附带专属 `Tab` 快捷键徽标）；
3. **毫秒级路径比对过滤引擎 (`itemMatchesScope`)**：
   - 支持 `drive-c`、`drive-d`、`desktop`、`downloads`、`documents`、`projects`、`folder-anycast`、`folder-easynote` 等预设以及任意自定义文件夹名称与物理路径的前缀比对匹配；
   - 支持双向联动分类分段计数（全部、应用、文件、文件夹、剪贴板）。

## 57. 筛选浮层视觉与交互深度纠偏（阶段三十八）

### 57.1 核心问题检讨与纠偏目标
依据用户关键审阅意见：
> **“这个 UI 违背了几个问题，无底色，无边框，配色适配项目，蓝色不适配呀，你得简单修改下，其他我觉得没问题了”**

在之前的快速迭代中，筛选浮层与日历组件引入了 Windows 原生控件的传统惯性样式，产生了如下严重背离项目设计哲学的硬伤：
1. **违背“无底色”**：浮层底色采用了接近实黑的不透明深色（`rgba(22, 25, 33, 0.95)`），在通透的桌面壁纸亚克力主窗体上形成了一块生硬突兀的“黑膏药”；同时浮层内搜索框、选项激活态等额外加深了不同层次的背景色，产生沉重色块感；
2. **违背“无边框”**：浮层本身、外层胶囊、浮层内搜索框、日历单元格、操作按钮等都带有 `1px solid rgba(255, 255, 255, 0.12)` 或高光内边框，违背了项目“极简沉浸、零生硬分割线与外边框”的核心法则；
3. **违背“配色适配项目，蓝色不适配”**：大量硬编码了 Windows 10/11 亮蓝色（`#0078d4`, `#60a5fa`, `#93c5fd`, `rgba(0, 120, 212, ...)`），包括菜单选中项、对勾、日历选中胶囊、日历起止范围带、应用按钮、搜索框聚焦描边及自定义文件夹文字，与 Anycast 全局高雅素净的中性灰白色阶、透光亚克力微晶材质形成强烈视觉割裂。

### 57.2 核心重构方案与落地清单

## 61. 置顶展架折叠与展开界面抖动硬伤根治（阶段四十二）

### 61.1 抖动根因深度剖析
针对用户指出的明确问题：
> **“我发现折叠与展开之间会抖动，把这个问题修复一下可以结束了”**

经逐帧排查 CSS 渲染流水线与 JS 执行逻辑，定位到了导致“抖动 (Jitter / Layout Shift)”的四大根本原因：
1. **外框内边距 (Padding) 与标题高度动态跳动 (跳动源 1)**：
   - 原样式中，展开态为 `padding: 4px 16px 4px 16px;`，而折叠态被设置为 `padding: 2px 16px 2px 16px;`；
   - 导致用户在点击右上角折叠按钮瞬间，整个标题栏及按钮自身在光标正下方**发生 2px 的垂直位移**（上下跳跃），给光标交互带来极为强烈的“按钮在手下发抖”的错觉；
2. **异步属性过渡动画与 DOM 瞬时清空的时间错位 (跳动源 2)**：
   - `.pinned-shelf-section` 上定义了 `transition: all 0.2s cubic-bezier(0.16, 1, 0.3, 1);`；
   - 折叠时，卡片区域在 JS 中在 0ms 瞬间清空并触发高度坍塌，而容器的内边距和外边距却在接下来的 200ms 内缓慢蠕动缩圈（4px 渐变至 2px，6px 渐变至 0px），导致下方分类栏和结果列表先瞬间跳跃、再持续颤动 200ms；
3. **DOM 节点反复暴力销毁与重绘 (卡顿闪烁源 3)**：
   - 原 `renderPinnedShelf()` 在折叠时暴力清空 `el.pinnedGrid.innerHTML = ""`，在展开时又重新解析拼装 8 个卡片的 HTML 与多层嵌套 SVG，引发浏览器的强制同步重排（Reflow）与重绘（Repaint），产生瞬间的白屏闪烁；
4. **底部浮动 Toast 弹窗引发的视线牵拉与双重运动 (干扰源 4)**：
   - 每次点击折叠/展开，均触发一次 `showToast("已折叠置顶快速访问")`，窗口底部瞬间触发带有 `translateY(8px)` 的弹跳气泡，形成“顶部折叠跳动 + 底部弹窗跳出”的视线拉扯。

### 61.2 彻底根治重构细节
1. **锁定恒定坐标与零位移布局 (Pixel-stable Rigid Layout)**：
   - `.pinned-shelf-section` 在展开态与折叠态下**强制保持完全一致的内边距**：`padding: 4px 16px;`；
   - `.pinned-shelf-header` 锁定刚性高度 `height: 20px; line-height: 20px;`；
   - 折叠按钮 `#togglePinnedBtn` 锁定固定尺寸 `width: 20px; height: 20px; flex-shrink: 0; margin: 0;`；
   - 结果：折叠与展开过程中，标题行与按钮的绝对屏幕 Y 坐标精确恒定，**在光标下绝对 0 位移**！
2. **彻底移除所有异步 CSS 容器过渡动画**：
   - 彻底删除 `.pinned-shelf-section` 的 `transition: all 0.2s`，避免异步缓动造成的二次颤抖；
3. **DOM 节点常驻与纯 CSS 极速显隐**：
   - 重构 `renderPinnedShelf()`：初始化只渲染一次卡片 DOM，折叠时仅切换 `.collapsed` 类，由 CSS `display: none !important` 瞬间隐藏 `#pinnedTrackWrapper`；展开时即刻呈现已有 DOM，零重绘重排开销；
4. **剔除无谓的底部 Toast 提示**：
   - 移除 `togglePinnedShelf` 中的 `showToast`，视觉焦点集中在当前面板，干净纯粹；
5. **版本递增**：
   - 样式表与脚本版本号统一更新至 `v=20260921_2587`。

## 65. Slint 原生端与 HTML 高保真设计图 1:1 逐项走查、亚克力失效根因诊断与系统性修复规划（阶段四十六）

### 65.1 走查背景与用户反馈
用户启动编译运行原生桌面客户端后发现，当前运行界面与此前经过 45 个阶段精心打磨的 `index.html` 高保真原型呈现出严重脱节与视觉崩塌。用户明确指出：

经过对 `index.html` 设计图与当前 `ui/`、`src/gui/`、`src/core/` 源码的像素级深度走查，完成了全面的全景对照清单与技术根因诊断。

### 65.2 核心硬伤一：为什么亚克力背景在 Slint 中完全没有做到？
在运行截图中，整个窗口呈现为 100% 不透明的死黑底色（`#0e1014`），毫无透光感，更没有任何桌面壁纸或背后窗口的高斯模糊渗出（Acrylic / Mica 彻底失效）。根本原因包含以下三重物理阻断：

1. **Win32 窗口样式缺失导致 DWM 拒止系统 Backdrop**：
   - Windows 11 22H2+（Build 22621+）的 DWM 系统级亚克力材质（`DWMWA_SYSTEMBACKDROP_TYPE = DWMSBT_TRANSIENTWINDOW (3)`）对窗口的基础样式有严格准入条件；
   - 当 Slint 声明 `no-frame: true` 时，底层 Winit 创建的是无边框、无标题栏的裸窗口（剥离了 `WS_CAPTION` 和 `WS_THICKFRAME`）；
   - **DWM 对不带 `WS_THICKFRAME` 的裸窗口默认拒绝注入 Mica 或 Acrylic 漫反射材质**，导致 API 虽然调用成功，但 DWM 根本不予着色处理；
   - **解决方案**：在 HWND 创建后，必须通过 `GetWindowLongW` / `SetWindowLongW` 为窗口强行补回 `WS_THICKFRAME` 样式，并调用 `SetWindowPos(SWP_FRAMECHANGED)` 强制刷新 DWM 帧架构。

2. **Skia 渲染管线与帧缓冲 Alpha 通道被纯色阻断**：
   - Slint 的 `renderer-skia` 渲染器在渲染时，如果根容器被赋予了不透明底色，或者底层 ClearColor 不是 `0x00000000`，Skia 就会将黑色填入帧缓冲；
   - 在 `ui/styles/tokens.slint` 中，`acrylic-bg` 被定义为 `#14171fb8`（不透明度高达 72%），当 Skia 无法穿透至 DWM 时，该颜色叠加在黑色底层上直接退化为死黑盒子；
   - **解决方案**：必须确保根窗口背景为 100% 透明，并通过 `DwmExtendFrameIntoClientArea(hwnd, &MARGINS { -1, -1, -1, -1 })` 将 DWM 客户区帧完全扩展至整窗，同时辅以微晶折射渐变层叠。

3. **缺少 Windows 10/11 组合属性（AccentPolicy）双重兜底**：
   - 部分 Windows 环境或系统设置中“透明效果”被关闭时，`DWMWA_SYSTEMBACKDROP_TYPE` 会无声失效；
   - **解决方案**：必须引入 `SetWindowCompositionAttribute`（`ACCENT_ENABLE_ACRYLICBLURBEHIND`）作为双重兜底，即便新版 DWM 接口异常，依然能强制拉起系统亚克力模糊。

### 65.3 核心硬伤二：75% 纯黑虚空的逻辑 Bug
- **根因**：位于 [`src/core/search.rs`](file:///d:/Anycast/src/core/search.rs) 的 `idle_items()` 空闲推荐逻辑中写死了 `if items.is_empty()` 的互斥分支；
- 用户剪贴板刚复制了 2 条随机字符串，导致 `items.len() == 2`，判定为非空后**直接跳过了全部 136 个扫描出的常用应用程序与最近文件**！
- 560px 高的视口仅排了 2 行简陋长条，下方 350px 彻底沦为一大片死寂的纯黑虚空；
- **解决方案**：重构 `idle_items()` 为混合流模式（常用应用推荐 12 项 + 最近项目 8 项 + 剪贴板 4 项），自然饱满填充视口。

## 66. 设置面板「关闭主窗口时最小化至托盘」开关移除（阶段四十七）

### 66.1 需求背景与死开关判定

用户提出质疑：**「我的设想中这个项目是不需要 app 的，打开为啥任务栏会有个图标呢」**。
由此排查出任务栏图标问题（见 `doc/实施进展与已知问题.md` 第 7 节），
并在同一轮里挖出设置面板里的一个**死开关**：`minimize_to_tray`。

深挖后确认它比「没人读」更彻底 —— **它背后的功能根本不存在**：

- 窗口 `no-frame: true`，没有系统标题栏最小化按钮；`.slint` 里搜 `minimize`
  只命中设置面板那一行开关 → **没有任何最小化入口**
- 唯一的隐藏入口 `hide_window()` 无条件执行 `ui.hide()` → 程序**一直**在
  「隐藏到托盘」，开关并不参与门控
- 任务栏按钮已被移除 → 「关掉开关 → 不隐藏到托盘」会把窗口彻底弄丢，
  托盘是现在唯一常驻的锚点

**裁决：移除开关。**
