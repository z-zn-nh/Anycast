# Anycast — 各模块硬约束速查

> 从 `memory/MEMORY.md` 拆出来的**细节版**（原文件超长会被注入截断，正文只留索引）。
> 每一项都是**跨会话仍然有效**的硬约束：判据数字、不能删的守卫、已实测无效的路。
> 按模块查，改到哪块先读哪块。


**窗口样式**（§10，skill `windows-frameless-window-style`）：`GWL_STYLE` → `theme::ensure_dwm_admissible`；
`GWL_EXSTYLE` → `theme::enforce_taskbar_exclusion`。⚠️ 一次 `hide()`→`show()` 后 winit 会重置窗口属性 →
`Gui::fix_taskbar` **不能加「只做一次」守卫**（两个底层函数都幂等早退）。显示态 exstyle `0x190`（含
`TOOLWINDOW`）、隐藏态 `0x40110` —— **别把隐藏态当缺陷**。主窗口是 topmost（`0x198`）→ 普通程序盖不住，
而**激活本窗口能升到 topmost 对手上面**（§12.4）。
🔴 `rt_probe.py::force_foreground` 会**摘掉 `WS_EX_TOPMOST`**，而样式校正**只补 `TOOLWINDOW`** → 碰过一次就
**整个进程生命周期不再置顶，除非重启**。**测「谁盖住谁 / 提示会不会被挡」时绝不能调它。**
🔴 **激活态一变，DWM 会把原生标题栏画到窗口上**（§12.5.4）：本窗口用了
`DwmExtendFrameIntoClientArea(MARGINS{-1,-1,-1,-1})` → **样式位全干净也照样看得见**，一直留到下次
hide→show；触发**双向**，只在「可见 + 激活态变化」时暴露（`suppress_blur` 路径）。判据 = 窗口顶部
**420×30 条带平均亮度**（干净 ≈45~75，残留 ≈241）。**唯一有效 = 真改一次窗口尺寸再改回**（`+1px` 立刻
还原）→ `theme::nudge_surface(hwnd)`，⚠️ **必须换线程发**（本线程内 winit 的 `send_event` 会缓冲
`Resized`）。**已实测无效的清单见 §12.5.4，别重复走。** 检测（§12.5.5）= `SetWinEventHook(
EVENT_SYSTEM_FOREGROUND)` + `poll_tick` 200ms 兜底；由 `blur_will_hide` 挡掉「马上要被隐藏」的那些次
（**只跳过扰动，不跳过 `last_fg` 更新**）。⚠️ 钩子回调**不能碰 `STATE`（RefCell）**（重入 panic）→
`static EVENT_HANDLER: OnceLock<SysHandler>`；⚠️ **不能按 `idprocess` 过滤**。
`ANYCAST_NO_FOREGROUND_HOOK=1` = A/B 对照，复跑 `tools/foreground_hook_ab_driver.py`。

**唤醒热键**（§12，skill `windows-global-hotkey-verification`）：`RegisterHotKey` → `WM_HOTKEY(id=1)` →
`WakeRequested` → `toggle_window()`。**注册失败必须让用户看见**（窗口不可见时存 `pending_toast`）；
`probe_hotkey` 里「与自身已有组合相同则放行」的守卫**不能删**。⚠️ `handle_commands` 在 `RefCell` 借用期间
被调用 → **回调 handler 必须延后到借用释放后**（重入 panic）。
🔴 **`Alt+Space` 被本机 `pi-desktop-host-core.exe` 的 LL 钩子吞掉**（只查 `VK_SPACE`+`LLKHF_ALTDOWN`，
不查其它修饰键）→ 它**不占注册表**：`RegisterHotKey` 照样成功、`err=0`、**不弹 Toast**，但 `WM_HOTKEY`
永远不来 = **静默失效**。→ **「注册成功 ≠ 按得到」**：`WakeDelivery` 自检（先对照 `Ctrl+Alt+Shift+F13`）
+ `Settings.action("verify-wake")` + `tools/hotkey_swallow_probe.py`。被吞时界面**录不到该键** → 「重录」
不能替代「检测」。**默认唤醒键 = `Ctrl+Alt+Q`**（`settings.rs::default_wake_hotkey()`，须与
`settings_modal.slint` 初值一致）。
🔴 **任何会主动造成失焦的「自检/测试」动作，都必须先按住失焦隐藏**（§12.4）：自检注入按键会把占用键的
程序**叫出来抢焦点** → `hide_on_blur` 把窗口连结论一起藏掉，被藏掉的恰恰是「键坏了」这条最该看到的结论。
做法 = `UiState::suppress_blur_until: Option<Instant>`（**截止时刻而非布尔量**：布尔量忘了复位 = 失焦隐藏
**永久静默失效**）+ 结论回来时 `force_foreground`（⚠️ 先判可见）+ 续期盖住 Toast 寿命。

**设置页**（§11）：**设置页 = 中性灰，主窗口 = 蓝黑**；`sp-*` token **只服务设置页**，`settings_modal.slint`
里**不应再出现** `Theme.dark ?` 三元或主窗口 token；`widgets.slint` 是共享控件 → 加「可选属性 + 默认值」。
⚠️ **配色别目测缩略图，采样**；还原主题用 UI 切回（保存会补写 6 个 `ai_*` 字段）。
⚠️ **控件判据是「有没有消费方」，不是「写没写进 config」** —— 已修 4 处「写了配置但 `src/core/` 里没有读取
点」的控件；无编译/运行期报错，只能逐字段 grep。**纯展示层开关改完必须立刻重绘**。

**搜索候选截断**（§9，skill `two-stage-ranking-truncation-audit`）：**不变量 —— SQL 侧任何截断都必须由「档位
键」守卫，不能只按 `length` 排**（`name_score` 前三档是**常数分**，只有「包含」档带长度惩罚 → 只按长度排 =
拿「名字短」当「相关度高」，前缀匹配**整档**被挤出 LIMIT，实测 0/40 → 40/40）。第二段是 `sort_by`
（**稳定排序**）→ **问题永远只在候选集**；`FILE_CANDIDATE_CAP = 3000`。

**判断模型 Phase 2**（doc `检索增强与判断模型接入开发文档.md`）：**只做「听懂」（意图解析 + 路由），不做
「排名」**。三级闸门 ① 本地规则（<1ms，纯关键词不调模型）→ ② 本地模型 → ③ 云端（**超时 800ms 放弃**）；
**首屏永远本地**、失败**静默降级**。⚠️ **两套 `Intent` 别合并**：`search::parse_intent` 产出**关键词**，
`decision::bridge::apply` 产出**筛选范围**；**模型禁止生成关键词**。
⚠️ `TypeSlot::to_scope_category()` 的每个返回值都必须在 `storage::type_extensions` 或 `item_in_scope` 里有
分支，否则 `unwrap_or(true)` **静默放行全部文件**。`PASS_THRESHOLD = 0.5` 别随手改（12 个用例夹在
(0.46, 0.59]）。

**索引层**（只借鉴 Everything 架构，**不集成**）：`files_fts` = FTS5 + **`trigram`**（**trigram 就是中文分词
方案**，不需要 jieba）；`name_score()` 四档；<3 字符走 `LIKE` 兜底。**NTFS 目录 mtime 语义**：增删/重命名
直接子项 → mtime **变**；改文件内容 → **不变**；孙目录变化 → **不变** → 可整棵跳过，**不需要管理员权限**
（实测 48268 文件 84.79s → **1.38s**）。最易重犯：① 任何 `metadata()` 失败都当「已删除」→ OneDrive 占位
文件整棵被抹 ② `content_fts.path` 是 UNINDEXED 列，查它 = `SCAN … VIRTUAL TABLE` → 改查 `content_meta`。
CLI（`src/core/cli.rs`，先于 GUI 拦截）：`--index-status/--index-compact/--index-scan/--index-watch`。
