## 2. Jev 是什么（事实层）

### 2.1 定位

Jev 是 **TypeSafe AI**（创始人 Diogo Almeida，前 OpenAI，InstructGPT / RLHF 论文共同作者）
于 2026-09-15 发布的**判断模型**，官方称其为第一个公开的 **「System One」模型**。

它**不生成文本**：不写文章、不写代码、不聊天。只在**有限选项**内做判断，
一次请求并行返回多个答案及其**置信概率**。一句话：**它是一个聪明的 if 语句。**

### 2.2 三种强类型输出（这是它能用的全部形态）

| 输出类型 | 含义 | 本项目用途 |
| :--- | :--- | :--- |
| **Choice** | 从预设选项里选一个 | 查询意图解析、类型判定、时间范围判定、路由选择 |
| **Score** | 在刻度上打分 | 候选结果重排 |
| **Noul** | 判断命题是否成立，返回 0~1 概率 | 结果是否满足用户条件；是否需升级到大模型 |

强类型的意义：**结构上杜绝幻觉**。它不可能编造一篇不存在的文章，最多选错一个选项。

### 2.3 硬约束（写代码前必须知道）

| 约束 | 数值 / 说明 | 对本项目的影响 |
| :--- | :--- | :--- |
| 延迟 | 端到端 **70~500 ms**（大模型 3 s ~ 300 s） | 可用于交互路径，但仍远高于本地搜索的 5 ms |
| 成本 | 输入 **$0.042 / M token**，输出免费 | 成本可忽略 |
| 选项上限 | **255** 个候选 | 时间 / 类型等枚举**必须离散化**，不能自由生成 |
| 输入形态 | **仅文本** | 图片、二进制不可直接投喂 |
| 状态 | **无状态**，不记忆历史 | 用户偏好须自建存储层 |
| 中文 | 官方标注 CJK「可用但准确率不等同英文」 | **中文查询必须做本地前置处理** |
| 可用性 | 节点集中在美国西海岸，**中国大陆无法直接使用** | 须经本地代理（Clash 7897） |
| 准确率 | **并不高于大模型**：TypeSafe 自评 67.8% vs 基线 74.1%；Banking77 实测 81.0% vs Claude Opus 5 84.4% | **它提升的是速度与成本，不是准确率** |

### 2.4 结论：正确用法是分层，不是替代

```
规则  →  判断模型(Jev)  →  大模型  →  工具
       ↑ 高频、明确、低风险的判断题交给它
```

Jev 只在「从几个明确选项里做决定」时是利器。要求生成自由文本时它帮不上忙。

## 3. 与既有文档的冲突清单 ⚠️

> 本节是本轮最需要用户裁决的部分。

### 冲突 A —— 「Local-first」原则被打破（必须裁决）

- **旧文档 §2.1**：「默认情况下：**不依赖网络、不启动 AI、不调用云端服务**。」
- **冲突点**：Jev 是**云端 API**，且在中国大陆需经代理才能访问。
- **建议处置**：把 §2.1 改写为 **「Local-first by default, cloud-enhanced on demand」**，
  并补三条硬约束：
  1. 极速搜索路径**零网络**（现有 5 ms 指标不得被破坏）；
  2. Jev 调用可一键全局关闭，关闭后功能不降级为不可用，只是回退为纯本地；
  3. 调用失败 / 超时**自动降级**到本地极速搜索，不得让用户看到错误弹窗。

### 冲突 B —— AI 层技术路线被改变

- **旧文档 §20 / §25**：AI 层规划为**本地** `bge-small-zh` 量化模型 + `sqlite-vec` 向量检索
  + RAG + Reranker；设置页 AI 分组只有「本地量化模型 / sqlite-vec Extension / Lazy Loading」三项。
- **冲突点**：Jev 是**云端**，且它在流程中替代的是 **Intent Understanding** 与 **Rerank**
  两个环节，**不替代** Embedding / Vector Search。
- **建议处置**：
  - §20 流程图拆为两层：**本地向量层（可选）** + **云端判断层（可选）**，两者可独立开关；
  - §25 AI 分组新增 Jev 条目（见 §5.5）。

### 冲突 C —— 性能目标需要补充前提

- **旧文档 §27**：「AI：默认不启动」；「默认搜索：毫秒级响应」。
- **冲突点**：Jev 端到端 70~500 ms。若每次输入都调用，会直接破坏「毫秒级响应」。
- **建议处置**：§27 补充——
  - Jev **仅**在「智能模式」下触发，且输入须先经**本地规则**判定为自然语言
    （含动词 / 时间词 / 疑问词，如「找一下…」「昨天…」「哪个…」）；
  - **必须与本地搜索并行**：本地先出结果占据首屏，Jev 返回后**只做重排**，不得阻塞首屏渲染；
  - 纯关键词输入（如 `docker`）**永不**触发 Jev。

### 冲突 D —— Phase 顺序需要调整

- **旧文档 §26**：Phase 3 = 文件内容搜索 / FTS5 / USN Journal；Phase 4 = AI。
- **冲突点**：本轮同时要求「速度提升」与「自然语言检索」，而 Jev 本身**不提升准确率**。
  若先接 Jev 再补检索质量，会出现「能听懂问题但找不到东西」的尴尬。
- **建议处置**：**检索质量先行**（FTS5 + 中文分词 + 排序模型），Jev 接入排在其后。
  即把旧 §26 的 Phase 3 提到 Phase 4 之前（顺序对调）。

### 冲突 E —— 对「质量提升」的预期需要修正（最重要）

- **用户表述**：「要求搜索质量和速度**大幅提升**，并且**检索效果要更好**」。
- **事实**：**速度**可由 Jev（判断）+ FTS5（检索）共同大幅提升；
  **准确率不能靠 Jev** —— 官方数据表明它并不比大模型更准（见 §2.3）。
- **建议处置**：质量提升必须落在**本地检索链**上（见 §4）。
  Jev 的价值是「让自然语言查询能落到结构化条件上，且不产生幻觉」，
  而不是「让搜索结果更准」。**这一点必须先对齐，否则期望会落空。**

### 冲突 F —— 结果卡片与右键菜单规格缺失（属新增，非冲突）

- **旧文档 §11** 结果卡片字段为 Icon / Title / Subtitle / Type / Path / Action，**无终端相关操作**；
  **§12** 快捷键表**无右键菜单规格**。
- **现状**：`ui/components/context_menu.slint` 已实现 6 项 ——
  立即打开 / 在资源管理器中显示 / 进入此文件夹查找 / 复制完整路径 / 固定到置顶 / 从最近记录中移除。
  **其中没有终端相关项**。
- **处置**：属**新增内容**，写入 §5.3。

### 冲突 G —— 「快捷键唤起」是当前唯一未验证的前置项（P0 阻塞）

- **旧文档 §13.1** 已完整设计快捷直达；实现里 `launcher::activate_or_launch()` 已存在
  （已运行则前置激活，否则启动）。
- **冲突点**：`doc/实施进展与已知问题.md` §4 明确列为**待办**：
  「全局唤醒热键（Alt+Space）、快捷直达绑定的端到端真机验证」。
- 而用户本轮需求 #4 / #6 / #7 **全部依赖这条链路**。
- **处置**：**这是 P0 阻塞项**，必须先真机验证热键链路，否则新功能无处落地。

### 冲突 H —— 窗口已退出任务栏 / Alt+Tab，唤醒路径变窄（风险）

- **旧文档 §7** 仅要求「不是传统应用窗口」。
- **现状**：2026-09-24 的实现进一步置了 `WS_EX_TOOLWINDOW`，窗口**不再出现在 Alt+Tab**，
  也不进任务栏。唤醒只剩**托盘图标 + 全局热键**两条路。
- **风险**：若热键注册失败（被其他程序占用，如输入法、QQ、游戏加速器），
  用户将「找不到窗口」且无任何提示。
- **处置**：需补「热键注册失败的**显式提示**」+ 托盘兜底说明。

## 4. 检索质量提升：不依赖 Jev 的那一半（P0）

> **这一节才是本轮「效果提升」的真正来源。**

### 4.1 现状

| 项 | 现状 |
| :--- | :--- |
| 索引 | `walkdir` 全量 + `notify` 增量 → SQLite（约 4.8 万条 / 10.4 s） |
| 搜索 | SQLite 直查 + 内存打分，实测 `docker` 约 5 ms |
| 缺失 | 无 FTS5、无中文分词、无内容索引、无 USN Journal |

### 4.2 提升项（按性价比排序）

| 优先级 | 措施 | 预期收益 | 备注 |
| :-: | :--- | :--- | :--- |
| **P0** | SQLite **FTS5** 全文索引（文件名 + 路径 + 内容） | 子串 / 词级检索从 O(n) 全表扫降到索引查找 | 见下方警告 |
| **P0** | **中文分词**：FTS5 `trigram` tokenizer，或 jieba-rs 预分词后入库 | 中文查询不再依赖 `LIKE '%…%'` | 二选一，建议先试 trigram |
| **P0** | **排序模型**：前缀命中 > 词首命中 > 中间命中；叠加使用频率 / 最近使用 / 类型权重 | 「检索效果更好」的直接来源 | 纯本地，零成本 |
| **P1** | 拼音首字母（项目已有 `pinyin` 依赖） | 输入 `vs` 命中 Visual Studio | 依赖已存在 |
| **P1** | **USN Journal** 增量替代 walkdir 全量 | 索引从 10 s 降到近实时 | 需 Win32 |
| **P2** | `sqlite-vec` + 本地 `bge-small-zh` | 语义相似检索（**不依赖网络**） | 模型体积待评估 |

> ⚠️ **注意**：`Cargo.toml` 中 `rusqlite` 当前只启用了 `bundled` 特性。
> 启用 FTS5 需追加特性（如 `bundled-full` 或显式 `fts5`），
> **会触发 SQLite 重新编译**——在提交量受限的机器上请预留编译时间（见 `.cargo/config.toml`）。

## 5. Jev 接入设计

### 5.1 定位：只做三件事

```
用户输入
   │
   ├─ ① 意图解析（Choice / Noul）→ 结构化条件
   │
   ├─ ② 路由（Choice）→ 极速 / 智能 / 混合
   │
   └─ ③ 重排与校验（Score / Noul）→ 对本地召回结果排序、判定是否满足条件
```

### 5.2 意图解析的选项设计（受 255 上限约束）

时间必须**离散化**为枚举，示例：

| 维度 | 候选选项 |
| :--- | :--- |
| 类型 | 全部 / 文档 / 代码 / 图片 / 音视频 / 压缩包 / 可执行 / 文件夹 |
| 时间 | 今天 / 昨天 / 本周 / 上周 / 本月 / 今年 / 更早 / 不限 |
| 位置 | 不限 / 当前目录 / 指定盘符 / 常用目录 |

> **关键设计：关键词不由 Jev 生成。**
> Jev 只做 Choice / Noul，不产出自由文本——这正是它杜绝幻觉的机制。
> 因此**关键词提取必须留在本地**（分词 + 拼音 + 已有索引的倒排召回），
> Jev 只负责把「昨天」「文档」这类**语义槽位**填进预设选项。

**示例**：输入「找一下我昨天修改的 EasyNote 文档」

```
本地：分词 → 关键词 = [EasyNote]（召回用）
Jev ：Choice(类型) = 文档
      Choice(时间) = 昨天
      Noul(是否要求含 EasyNote 关键词) = 0.94
→ 本地按条件过滤 + 排序 → Jev Score 重排 → 输出
```

### 5.3 右键操作扩展（新增）

在 `ui/components/context_menu.slint` 增加「打开方式」分组：

| 菜单项 | 适用 | 实现方式 |
| :--- | :--- | :--- |
| 在终端打开（cmd） | 文件 / 文件夹 | `cmd.exe /K cd /d "<dir>"` |
| 在 PowerShell 打开 | 文件 / 文件夹 | `pwsh.exe -NoExit -Command Set-Location -LiteralPath '<dir>'` |
| 在 Windows Terminal 打开 | 文件 / 文件夹 | `wt.exe -d "<dir>"`（先探测是否存在） |
| 用…打开 | 文件 | **已有** `shell_open_with(target, "", "openas")` |
| 打开所在文件夹 | 文件 | **已有** `reveal_in_explorer()` |

规则：
- **文件**取父目录，**文件夹**取自身；
- 终端启动须用 `CreateProcessW` 并**显式设置工作目录**，避免窗口闪退；
- 需探测 `pwsh.exe` / `wt.exe` 是否存在，缺失则隐藏该项（`cmd.exe` 恒在）。

### 5.4 唤起与关闭

| 行为 | 现状 | 说明 |
| :--- | :--- | :--- |
| 唤起 | 全局热键 `RegisterHotKey` + 托盘 | 已实现，**未真机验证**（冲突 G） |
| 关闭 | 点击非自身区域 | **已实现**。机制为 200 ms 轮询 `GetForegroundWindow() != hwnd` |
| 宽限 | 显示后 600 ms 内不失焦关闭 | 已有 `shown_at` 宽限逻辑 |
| 抑制 | `state.suppress_blur` | 原生文件对话框 / 热键测试期间置位 |

> ⚠️ **重要提醒**：失焦关闭基于**前台窗口比对**。
> 应用内右键菜单与设置面板是 Slint **同窗口绘制**，不受影响（已确认）。
> 但若将来引入**原生 Shell 右键菜单**（独立 popup 窗口），会**立即触发误关闭**，
> 必须复用 `state.suppress_blur` 包住。

### 5.5 设置页新增项（对应旧 §25 的 AI 分组）

```
AI（AI 语义引擎）
├── Enable AI Search          智能语义总开关
├── Jev API Key               云端判断模型凭据
├── Jev Proxy                 代理地址（默认 http://127.0.0.1:7897）
├── Confidence Threshold      置信度阈值，低于此值回退本地 / 交大模型
├── Call Policy               触发策略：仅自然语言输入 / 每次智能搜索
├── Fail-safe Degrade         失败自动降级到本地极速搜索（默认开）
├── Model (本地量化模型)       bge-small-zh
├── sqlite-vec Extension      向量加速
└── Lazy Loading              按需动态唤醒
```
